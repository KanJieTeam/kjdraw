# KJDraw 1.0.0-rc.2 — Release Candidate

Status: in development. This candidate has not been published to npm or promoted to a stable release.

This update makes KJDraw easier to embed, explore and extend. It builds on [1.0.0-rc.1](1.0.0-rc.1.md) with a public editor API, framework components, a reorganized documentation site and original industry drawings.

## Editor and frameworks

- `createKJDrawEditor` mounts the editor and exposes file open/save, commands, selection, history, appearance and lifecycle events.
- `/react` and `/vue` provide `KJDraw` components with real framework types. Appearance updates preserve the active drawing.
- `/core`, `/files`, `/agent` and `/plugins` organize application-facing entry points. Existing low-level exports remain available.
- `/renderer/canvas` provides shared Canvas rendering, navigation, selection and scene-provider integration.

## Drawings and workbench

- `/samples` contains original site, architectural, road-profile and mechanical drawings. Each can be loaded into an embedded editor, edited and exported.
- The demo opens a complete sheet, adds a five-drawing sample library and separates the left layer panel from the right Properties/Agent tabs.
- Input fields no longer trigger destructive canvas keyboard shortcuts.
- Shared-SDK editors keep command targets and document lifetimes separate, and disposing an editor cancels a pending save before it can trigger a download.
- Repeated sample creation preserves existing drawings; architectural sample geometry uses the dimensions shown by its annotations.

## Documentation

- Task-oriented bilingual guides cover installation, files, commands, frameworks, plugins and Agent integration.
- The main API page explains editor options, methods and events; generated low-level declarations move into a separate reference.
- README examples use the public editor and framework components.

## Release infrastructure

The first candidate passed the Node 22/24 matrix on Windows, macOS and Linux, Rust tests, the Chromium/Firefox/WebKit launch journey, and GitHub Pages deployment. Its independent DXF job stopped before executing because `setup-python` pip caching requires a dependency file to hash. This candidate adds the pinned `scripts/audits/requirements-dxf.txt`, binds the cache to that file, and installs the same `ezdxf==1.4.4` pin from it. No CAD compatibility assertion was weakened.

It also prevents release tags from launching a duplicate CI matrix: the branch run remains the immutable release gate, and the annotated tag points at that exact commit.

`scripts/audits/verify-live-site.mjs` checks deployed assets against the local release checkout and exercises the workbench and documentation on their public URLs.

Use a repository checkout to test the candidate before publication. The npm version badge in the README identifies the currently published package.
