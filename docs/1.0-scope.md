# KJDraw 1.0 product contract

KJDraw 1.0 is embeddable 2D engineering-CAD infrastructure, not a claim to reproduce every desktop CAD feature. Its stable promise is deliberately narrow enough to test and broad enough to build real applications.

## Stable 1.0 promise

- A strict TypeScript, ESM-first SDK with generated declarations, zero runtime npm dependencies and documented root/subpath exports.
- Transactional KJD documents with deterministic commands, revisions, undo/redo, selection, snapping and declared 2D editing operations.
- KJP project packages for multiple drawings, manifests, snapshots, journals and integrity validation, with documented resource budgets.
- ASCII DXF interoperability for the exact published entity/resource/version matrix. Unsupported semantics are reported; arbitrary-DXF losslessness is not implied.
- A bilingual browser workbench that can open, inspect, draw, edit, review, undo, save and reopen through public SDK APIs.
- Review-bound Agent plans using versioned cryptographic content binding, expiry, one-shot execution and auditable receipts. Identity and authorization remain host responsibilities.
- Optional Rust/WebAssembly authority and deployment-provider contracts whose fallback and network behavior are explicit.
- React and Vue integration examples compiled against the same packed npm artifact.
- Versioned documentation, generated API reference, reproducible tests, performance budgets and signed/provenanced release artifacts.

## Explicit non-goals

KJDraw 1.0 does not claim DWG support, arbitrary-DXF lossless conversion, a general BRep solid modeller, full parametric constraints, real-time collaboration, proprietary engineering templates, complete font/layout fidelity or device-certified plotting. Experimental mesh features remain clearly labelled. Plugins declare cooperative permissions; hostile-code isolation belongs to the host process or sandbox.

These non-goals are not hidden backlog items. Each would need its own public contract, legal/provenance review, fixtures and executable acceptance evidence before being advertised.

## Promotion rule

The stable tag is cut only after every `requiredForStable` gate in [`KJDRAW_1_0_ACCEPTANCE_MATRIX.json`](KJDRAW_1_0_ACCEPTANCE_MATRIX.json) passes on the exact release-candidate commit. The packed npm artifact, live Demo, versioned Docs and GitHub release assets must all resolve to that commit. Community attention cannot be guaranteed; a truthful contract and independently reproducible evidence are non-negotiable.
