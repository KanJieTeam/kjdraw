# AI conversation and versioned capability foundation — 2026-09-10

The playground previously exposed three fixed example changes as its entire Agent panel. It now provides a conversation log, editable composer, recent conversation context, model connection settings, cancellation and inline proposal review. The existing examples remain available in a collapsed Local examples section. This uses the existing model adapters, isolated geometry previews and host approval flow; it does not generate or execute model code.

The user configures a same-origin model proxy and explicitly sends a request. The local development server can supply `/api/model` using server environment configuration. Model credentials stay on the server. Four protocol transports are supported; each actual model still requires its own acceptance. Public static hosting does not supply model credentials or a model endpoint. Conversations are currently memory-only, bound to the selected document, and include a bounded recent history. The loop is non-streaming. Its progress events reflect actual model, read, measurement and proposal operations and disclose no geometry payload or model reasoning.

Review cards support canvas overlays, apply/discard, undo and KJP save. Drawings remain unchanged until host approval. Tests cover cancellation, late responses, document changes, clearing a conversation during approval, old-result undo after a subsequent edit, untrusted text and oversized messages. Epoch and document-identity checks keep old responses and overlays out of a new conversation. Technical model errors remain separate from success receipts.

The new `KJAgentCapabilityRegistry` accepts bounded plain JSON domain manifests. It supports exact semantic versions, content-change locks, explicit upgrades, tool API compatibility and host-selected tools. The runner consumes the locked instructions and narrows its tool set to the selected capabilities within the host allowlist. Registering a new version does not change an existing project lock. Locks survive KJD and KJP round trips when the host stores them in project/document metadata. The fingerprint detects changes; it is not a signature or publisher authentication. Requirements inside a capability are requested evidence descriptions, not executed geometry validation or certification. There is no automatic download, marketplace, training or silent upgrade.

These are foundations for the README's intended complex-drawing workflow.
