# Filtered agent drawing queries

Date: 2026-09-10. Source increment after `8b4ebbc`; accepted source is the commit containing this record. Package publication and stable 1.0 remain pending.

The previous model tools could read only the first visible model-space page and its unfiltered continuations. `cad_query_drawing` now exposes the existing context engine's exact IDs, entity types, layer IDs, owner space, visibility options, revision-bound offsets and output limits. A typed `KJAgentDrawingQuery` is available from the package. Filters intersect; omitted filters are unrestricted, empty arrays match nothing. Optional filter properties remain strictly validated; mandatory properties of all existing tools still reject omissions. The new tool is appended as the eighth definition, preserving the previous order. Hosts can select it with `toolNames`.

The shared context engine also accepts `bounds: [minX,minY,maxX,maxY]` in owner XY. It reuses CAD selection primitives and analytic curve intersections, including segments crossing a view whose endpoints are outside. Known supported geometry is marked `intersects`; unsupported types, tilted normals and oversized polylines are retained as `unclassified`, never silently discarded as outside. Coordinates remain native; blocks are not expanded. `spatialQuery` records the rectangle and semantics. This conservative classification is not a complete rendered-visibility or paper-viewport implementation.

Validation:

- Node 22 and Node 24 full suites: **390/390 each**, including packed JavaScript/TypeScript/React/Vue consumers. The installed tool-session example exercises the new region query, and the consumer type fixture compiles `KJAgentDrawingQuery`.
- Chrome 152, Firefox 155 and WebKit 26.6: **24/24** Agent/editor and bilingual documentation browser cases. The new case converts actual canvas corners through `screenToWorld`, queries the visible region, approves a local move, verifies unrelated geometry, undoes/redoes, pans to another region and saves/reopens through the public editor.
- Four protocol regressions pass filtered query → exact returned IDs → MOVE proposal → host review/approval → unchanged unrelated entity → undo/redo → DXF reopen. Existing default tools, error correction and runtime permission tests remain active.
- Context tests cover locked/hidden entities, paper ownership, combined/empty filters, malformed/sparse bounds, excessive limits, stale revisions, no mutation or private metadata disclosure, line/ray/arc/circle intersection and uncertainty. A 2,000-line case pages an 11-line region under **1,024 bytes per response**, makes forward progress and returns the exact expected IDs.
- Existing spatial-selection tests pass, retaining analytic curve/bulge behavior and the editor's established selection semantics. Runtime/declaration/API/documentation generation, strict types and repository checks pass.
- Six private files were read locally with source hashes checked before and after. Five LINE-bearing cases query a small region containing a selected source endpoint; each returns that target without changing the document fingerprint/revision. Visible LINE populations **106 / 1,412 / 4,000 / 454 / 46** produce **2 / 2 / 2 / 5 / 1** returned objects and **1,289 / 1,173 / 1,282 / 2,476 / 891** UTF-8 context bytes. The sixth file has no LINE and is explicitly skipped for this query. These are local read checks, not real-model quality or timing comparisons. No source coordinates, filenames, text or screenshots are published.

The existing offline schema comparison remains executable. Appending a tool increases the full eight-tool schema to 9,928 / 9,912 / 9,680 / 9,771 bytes across the four protocols; a host selecting just read/circle still sends 1,431 / 1,427 / 1,369 / 1,412 bytes. Historical seven-tool results are retained in the prior acceptance record. Byte counts are not provider tokens, fees or model-success measurements.

Continue a filtered query with the same tool, identical filters and returned revision; `cad_read_page` does not remember filters. Set a finished entity/layer collection's limit to zero. Output caps do not bound full scan time or initial snapshot memory, and the response cap excludes the outer tool-result wrapper. Unknown spatial results need inspection. Text, HATCH, INSERT, ellipse/spline and complete paper viewport classification remain open; complex repeated real-model evaluations, actual token/cost measurements and the broader 1.0 gates remain unfinished.
