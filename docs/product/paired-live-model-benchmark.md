# Paired live-model drawing experiment

This runner evaluates the same three fully specified synthetic tasks used by the earlier pilot. It compares one KJDraw drawing-tool proposal with one direct ASCII DXF answer from the **same configured model and Chat Completions endpoint**. It does not yet evaluate autonomous complex drawing, multi-turn repair, another CAD product, or all four model protocols.

## Dry run and explicit live configuration

The default command prints the full request plan and makes **zero network requests**:

```sh
node scripts/benchmarks/paired-model-benchmark.mjs --repetitions=5 --max-requests=30
```

Five repetitions × three tasks × two arms require 30 requests. A smaller request budget is rejected before creating a report directory or contacting the provider. The supported range is 5–30 repetitions and at most 180 requests. There are no automatic retries or hidden warmup requests to the model.

Install the independent validator into your selected Python environment:

```sh
python -m pip install -r scripts/audits/requirements-dxf.txt
```

Set these server/process environment variables explicitly; the runner never searches private application configuration or credential stores:

| Variable | Meaning |
| --- | --- |
| `KJDRAW_BENCH_PROTOCOL` | Exactly `chat-completions` in this implementation |
| `KJDRAW_BENCH_MODEL` | The same requested model in both arms |
| `KJDRAW_BENCH_ENDPOINT` | Complete remote HTTPS Chat Completions URL, without credentials, query or fragment |
| `KJDRAW_BENCH_API_KEY` | Provider key supplied by your secret manager or process environment; never written to artifacts |
| `KJDRAW_BENCH_THINKING` | Optional `disabled` or `enabled`; the same provider `thinking.type` setting is sent and recorded for both arms. Omit it for providers that do not support this field. |
| `KJDRAW_PYTHON` | Optional Python executable with the pinned `ezdxf` dependency; defaults to `python` |

Then explicitly opt in to the potentially billable experiment and select a **new** output directory:

```sh
node scripts/benchmarks/paired-model-benchmark.mjs --live --output=.cache/paired-model-run --repetitions=5 --max-requests=30 --timeout-ms=60000
```

Live mode rejects loopback endpoints and plain HTTP. Local fake-provider tests use a separate `fixture` mode restricted to HTTP loopback; fixture output cannot be labeled live or used as public model evidence. No charts or rankings are generated by this runner, and every live report requires publication review.

## What is measured and retained

Both arms use temperature 0, a 4,096-token output limit, non-streaming requests and identical task requirements. Arm order alternates across tasks and repetitions. The tool arm uses the actual SDK proposal/review path on a new synthetic document. The direct arm supplies DXF text. Both outputs go through the existing independent `ezdxf` validator for geometry, units and audit errors/fixes; validator availability is checked **before** the first provider request.

The new validator first enforces the native request contract: R2013 or newer, model-space geometry only, zero native Z/elevation/thickness, positive-Z extrusion normals, zero polyline widths, and only the requested entity types. It then uses the historical XY comparator. A shape with matching XY coordinates but different 3D position, plane or width is rejected. The earlier pilot validator remains unchanged as a historical artifact.

`report.json` retains every attempted request, model identifiers, fixed settings, normalized provider usage, cache-read counters, reasoning-token counters when reported, transport wall time, end-to-end time, validation, failures, source/runtime hashes, and the count of unexecuted requests. Counters use `extractKJModelUsage`: missing or invalid data remains `null`, invalid field paths are retained, and cached input is not added again to inclusive input totals. Cost stays `null` because this runner has no verified price table. Transport time includes network/provider work; it is not a direct measurement of server inference time. End-to-end time includes final-output capture, SDK work where applicable, independent validation and artifact writes.

Request bodies and a fixed whitelist of final answer/tool-call fields are saved with SHA-256 hashes. Provider headers, credentials, hidden reasoning text and arbitrary provider extensions are not saved. Requested and returned model names are kept separately; a missing or inconsistent returned model is visible in `consistentReturnedModel`. UTF-8 request bytes are recorded separately from reported tokens.

A nonempty provider refusal is recorded as `MODEL_REFUSED`, with reported usage retained and refusal text omitted; accompanying tool calls are never applied. Credential reflection checks inspect retained string values and their JSON-escaped form, including quoted or backslash-containing keys. Cache-miss and reasoning-token aggregates use the shared usage parser rather than a second provider-specific interpretation.

The report records a `requesting` entry before dispatch. If the process is interrupted, that entry means the provider outcome and possible cost are unknown; the runner does not automatically resume or replay it. HTTP/authentication failures, redirects, network errors, timeout, oversized responses or validator loss stop further requests and retain the remaining unexecuted count. Model output and geometry failures remain in the paired results. Existing output directories are never overwritten. Reports are checkpointed by atomic replacement inside the new run directory.

Before committing reviewed DXF artifacts, preserve their bytes with the repository's binary DXF attributes and compare committed blobs against recorded SHA-256 hashes. A text-mode newline conversion can invalidate a correct file's recorded hash. Live results must be reviewed with complete failure counts, matching model/settings, usage validity and output geometry before presenting any token, time or quality comparison.

## Local conformance test

The [integration test](../../packages/kjdraw-sdk/test/paired-model-benchmark.test.mjs) starts a loopback HTTP fake provider, runs all 30 requests through the real SDK and `ezdxf`, checks usage normalization and artifact filtering, and verifies immediate stops on provider errors and timeout. Its synthetic usage counters are only test data.

```sh
node --test packages/kjdraw-sdk/test/paired-model-benchmark.test.mjs
```

Set `KJDRAW_BENCH_INTEGRATION_REQUIRED=1` when validating the full path: missing Python/ezdxf then fails the test instead of skipping the three integration cases. Generic SDK environments without that independent dependency report explicit skips rather than substituting the SDK as its own independent validator. No test obtains real model credentials or makes remote provider calls.
