# Custom DXF hatch rendering acceptance

Date: 2026-09-10. Source increment following `880ce9e`; accepted source is the commit containing this record. No package publication or stable 1.0 release.

Imported custom HATCH entities previously retained pattern tags but were rejected by the Canvas renderer by name. The renderer and DXF writer now share actual line-family definitions: angles, bases, signed offsets, dash lengths, gaps and dots. Imported global angle/scale are applied once; subsequent MOVE, rotation, uniform scale and reflection transform the effective pattern and its boundaries together. Viewport clipping retains each row's phase, and compound boundaries clip holes with the even-odd rule. Continuous collinear definitions paint a single locus instead of dividing by zero.

The renderer budgets 20,000 work units per hatch and 100,000 per frame. It never enlarges the pattern spacing to hide excessive density. `hatchDiagnostics` identifies partial-budget drawing, unsupported pattern data and unsupported boundaries; the workbench inspector and playground display the limitation. LINE/ARC edge boundaries and polygon/bulge boundaries participate in fit. Block children retain explicit colors, BYBLOCK inheritance and visibility; selected blocks and previews retain their override color.

Validation:

- Node 22 and Node 24 full SDK suites: **372/372 each**, including packed JavaScript/TypeScript/React/Vue consumers. After the final block-color correction, **31/31** focused renderer, hatch and drawing-context tests pass; generated declarations and strict types pass.
- Public editor and React/Vue browser regressions: **27/27**. Final custom-hatch browser tests: **6/6** on Chrome 152, Firefox 155 and WebKit 26.6. Tests inspect real pixels for dashes, gaps, dots, holes and outside-boundary pixels, pan/zoom, a rotated/scaled block, selection, MOVE/undo/redo and public editor DXF save/reopen. Dense and unsupported-curve cases assert diagnostics. Screenshots use original synthetic geometry only.
- Independent ezdxf **1.4.4** import/export validates custom line angles, origins, offsets, dash lengths, transformed hole coordinates and zero audit errors/fixes. Existing independent DXF style/curve tests pass.
- Six private files retain layout counts, entity-type counts, units and text multisets; independently reopened outputs have zero audit errors/fixes. All original hashes remain unchanged. Five LINE-bearing files retain approved exact movement, unchanged unrelated entities, undo and redo; the sixth has no LINE.
- Individual local pixel comparison against a boundary-only rendering finds pattern pixels in **77/77, 46/46 and 60/60** previously missing hatches. No unsupported pattern diagnostics remain in these cases. **Four of the 46** dense hatches hit the budget and are only partially painted; visible pattern pixels are not proof that those four are complete. Private source data and screenshots remain local.

The final browser load matrix completed 54 runs (six files, three engines, three repeats), with zero call failures and zero external requests. Bundle SHA-256: `ca311f26372e03c282de1a84aee75aa8dbe08784f0d85a3da493729222cd3ed6`. KJDraw API-load medians in case order were **535.4, 455.9, 1490.1, 169.0, 108.4 and 128.4 ms**; dxf-viewer 1.0.48 medians were **283.6, 280.6, 351.6, 168.9, 170.1 and 189.6 ms**. Environment: i9-13900HX, RTX 4050 Laptop, Chrome 152, Node 24, 1280×800/DPR 1, preloaded local SimHei font. Editable document construction, viewer scene construction and parsing are different workloads; this is not a speed superiority result. All KJDraw cases report zero unsupported top-level entities; case 05 consistently reports four partial-budget hatches. Faster timing cannot erase that limitation. Earlier development and failed reports are retained separately.

Failed runs are retained: the individual pixel check exposed missing edge-boundary fit, and the new block test exposed insertion color overriding explicit child color. Both were fixed and the corresponding pixel assertions rerun without removal.

Scope remains limited: ellipse/spline boundary edges and non-whole-cycle collinear dashed families are explicitly unsupported; nonuniform block transforms, full hatch-style semantics, interactive boundary editing and production-output fidelity remain open. Canvas curve approximation and partial-budget rendering are not lossless display. This slice closes custom-pattern name rejection, not W04/W05/W10 or the full 1.0 gates. Private downstream Kanjie UI integration has not been claimed.
