## 本次完成的产品切片

同一套公开能力供普通用户、嵌入应用和 Agent 使用：选择边界、查看保留图形、应用一次修改、逐次撤销。没有另建只给 Demo 使用的几何实现，也没有引入某个模型供应商或隐藏服务。

| 使用者 | 新增体验 / 接口 |
| --- | --- |
| 普通用户 | 在 Demo 或嵌入工作台选择连续修剪/延伸，一次选边界、连续点目标；悬停先看保留图形，每次提交均可单独撤销。单次操作继续保留。 |
| 应用开发者 | 从 `@kanjieteam/kjdraw/boundary-edit` 导入 `createBoundaryEditSession`，自定义 UI 仍使用相同状态、几何预览和 SDK 执行路径。 |
| Agent 宿主 | 用实际预览产生的命令注册原有审核计划，用户批准后提交；拒绝、过期、图档变化、参数改变及重复执行继续受既有计划校验约束。 |

工作台保持既有 Precision 样式，增加紧凑的阶段、边界数量和完成次数提示。中英文切换保留会话；图档、修订、布局或只读状态变化时结束待执行操作。拖动、夹点和连续点选不会同时争用指针。离开画布清除悬停覆盖层，原生指针捕获丢失时不提交旧手势。

## 本轮额外发现并修复的问题

### 不能用“修订号加一”冒充应用了预览

初版连续会话仅检查执行后修订号增加一次。独立复核复现了：错误执行器提交其他命令、并发无关修改，以及修改取点参数后仍误报预览应用成功。

现在同时核对实际提交记录、SDK 回执中的图档/命令/信封/前后修订号、TRIM/EXTEND 参数摘要及保留图元的类型和完整规范化 payload。写入范围限于目标、预期派生图元及正确的 GROUP / SELECTION_SET 成员替换；顺带修改无关点、破坏组成员或写入其他资源均不会被计为成功。

普通提交检查操作记录，只有操作被压缩时才读取前后快照。包含 1001 个组的真实修剪回归覆盖了压缩路径：1003 条操作、全部组成员正确替换，一次撤销完整还原。

不一致时返回 `boundary-edit.unexpected-commit`，结束会话且不增加完成计数。宿主已提交的错误或其他修改不会被自动回滚；应检查图档后使用正常历史操作处理。这是错误集成检测，不是撤销任意宿主权限，也不是模型沙箱或密码学认证。

### 修改记录保留操作类型

原先 `object.create` 的数据里再次使用 `type` 保存实体类型，导致操作类型被 `LINE` / `ARC` 等覆盖。现在保留 `type: 'object.create'`，实体类型写入 `objectType`，压缩记录的 `byType` 因而按实际操作分类。实体自己的 `type` 不变，也不重写已有历史。
