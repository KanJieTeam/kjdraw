# KJDraw Precision

KJDraw 的界面首先是一套可以工作的 CAD 工作台。图纸是主体，工具区帮助用户准确操作；品牌识别来自稳定的色彩、几何图标和排版，不依靠宣传区或装饰卡片。

## 主题规则

| 元素 | 规则 |
| --- | --- |
| 工具区 | 珍珠浅灰 `#f6f7f9`、白色面板、细分隔线 `#d9dee6` |
| 绘图区 | 默认深色；嵌入组件的明暗选项控制画布，不改变工具区结构 |
| 操作色 | 蓝色 `#2863df`，用于选中、主操作和焦点；普通图标用中性灰蓝 |
| 品牌色 | 荧光绿 `#bdf878`，主要用于标志；不能覆盖图纸原有图层颜色 |
| 字体 | Segoe UI / PingFang SC / Microsoft YaHei；正文 13px，辅助标签不小于 12px |
| 控件 | 常规控件 32px、圆角 6px；统一 hover、focus、active、disabled |
| 图标 | 同一套 24×24 SVG、1.5px 线条；不用 Unicode 字符代替工具图标 |
| 布局 | 顶部应用栏与 Ribbon，中央画布，两侧工具面板，下方图纸标签和状态栏 |

共享源是 `packages/kjdraw-sdk/src/theme.ts`。嵌入式工作台直接使用主题常量和图标；Demo 的 `theme-tokens.css` 从同一源生成，布局只加载 `precision.css`，不再叠加旧的四份样式。`build-typescript.mjs --check` 检查生成文件是否一致。

这不是一个新增的公开主题配置 API。当前代码中的 CSS 变量是实现基础；正式的宿主覆盖接口、完整换肤和主题兼容承诺需要单独测试后再公开。

## 分项验收

自动化通过不等于视觉验收通过。每一项最终都需要实际页面证据和用户确认。

| 编号 | 本轮交付与验收动作 | 状态 |
| --- | --- | --- |
| UI-01 | 打开 Demo 与 Vanilla/React/Vue 编辑器，核对共用颜色、字体、图标；分别检查顶部、画布、两侧、底部是否形成完整工作台 | 待用户验收 |
| UI-02 | 中英文切换；检查所有控件的字号、间距、选中/悬浮/键盘焦点/禁用状态；同一工具图标不能丢失或变形 | 待用户验收 |
| UI-03 | 切换常用、绘图、修改、测量，实际点击工具；检查快捷键提示与可用状态，而非只有标签能点 | 待用户验收 |
| UI-04 | Demo 搜索图层、显示/隐藏、修改名称与颜色、撤销；拖动或用方向键调宽侧栏；属性内容不溢出 | 待用户验收 |
| UI-05 | 创建与选择对象、输入移动等命令；检查数值弹窗、修改反馈、撤销；普通属性区不输出原始 JSON | 待用户验收 |
| UI-06 | 在 1366×768、1440×900、1920×1080、390×844 检查页面横向溢出；切换侧栏后检查全图适配与手动视图；另验收高 DPI | 待用户验收 |
| UI-07 | 检查重复品牌、PUBLIC SDK、90 秒场景是否移除；没有选择对象时有说明；Agent 区明确为预设审核示例，不冒充自由对话 AI | 待用户验收 |

浏览器回归：`tests/browser/precision-theme.spec.mjs`、`workbench.spec.mjs`、`launch-journey.spec.mjs`。本地验收截图输出至 `.cache/precision/`；发布前须重新核对部署页面，不能用本地通过代替线上通过。
