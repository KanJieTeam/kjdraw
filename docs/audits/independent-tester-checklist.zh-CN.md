# KJDraw 1.0 候选版独立试用清单

本清单用于收集可复查的问题与独立验收证据，不代表已经达到稳定 1.0。测试者应未参与本次候选版开发，使用干净项目与公开安装说明；测试过程中开发者不要远程指导。

## 开始前记录

- 候选版完整 Git SHA、包版本、安装来源（候选 tarball 或 npm）及包文件 SHA-256。
- 操作系统及版本、Node.js 版本、使用的智能体/模型、界面语言。不要记录或发送 API Key。
- 每项任务的原始提示词、开始与结束时间；失败时保留完整报错和截图。

## 统一任务

1. 从空白图纸绘制一个带孔的简单机械零件，并给孔径或长度加尺寸。不要导入现成图纸代替生成。
2. 再从空白图纸绘制一个勘察柱状图或剖面图；如果没有实测数据，必须在图内标明“示意、非实测”。检查文字、标高、深度线及地层花纹。
3. 在任一图纸中选中已有对象，修改一个明确尺寸或位置；执行撤销与重做，核对最终几何事实。
4. 保存 KJD、导出 DXF，分别重新打开。独立量测至少一个具名事实，例如“孔径 10 mm”或“钻孔深度 30 m”；不能只看截图。
5. 记录交互预览是否打开、可否缩放与选中对象、耗时、错误或异常字体；保留 KJD、DXF 与截图。私有项目图纸、报告和个人信息不上传公开仓库。

## 判定与提交

逐项写明通过/失败及复现步骤，不要把“看起来像”当作尺寸、可编辑性或重开一致性的证据。正式独立验收需要测试者提交包、KJD、DXF 三个 SHA-256，环境、任务 ID、具名几何核对与独立完成声明；维护者按 [外部验收协议](external-acceptance.md) 用 `record-external-acceptance.mjs` 校验报告和文件字节。

三模型门槛与普通试用不同：必须由三个不同厂商的真实模型（其中至少两个国内厂商）在至少两种操作系统上跑版本化 30 个案例，每模型至少五轮；详见 [跨模型保留集协议](three-model-holdout.md)。一次朋友圈截图或一位用户成功不能替代它。
