# DeepSeek Flash: compact one-shot drawing and end-to-end time (2026-09-29)

This is a **narrow, reproducible synthetic comparison**, not a claim that KJDraw always saves tokens or time. The three fixed tasks are a mounting plate, a bolt flange, and a stepped profile. Each arm received five requests per task in each run, at temperature 0, with `deepseek-flash` and thinking disabled. No failed response was retried or manually corrected. KJDraw used compact geometry JSON, then the real SDK to produce DXF; the baseline asked the same model to produce complete ASCII DXF without a CAD library. Independent `ezdxf` checks determined success from units, audit, and exact task geometry.

| Run | KJDraw valid | Direct DXF valid | KJDraw tokens | Direct DXF tokens | KJDraw model time | Direct model time | KJDraw end-to-end | Direct end-to-end |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| A · original timing | 15/15 | 7/15 | 4,640 | 7,802 | 11.08 s | 19.46 s | not recorded | not recorded |
| B · fresh Node process per drawing | 15/15 | 7/15 | 4,640 | 7,772 | 12.15 s | 19.59 s | **20.025 s** | **19.692 s** |
| C · persistent Node host, fresh document per drawing | 15/15 | 9/15 | 4,640 | 7,850 | 12.38 s | 18.31 s | **12.685 s** | **18.391 s** |

Totals above sum all 15 requests per arm, not a simultaneous batch throughput test. Provider-reported input and output tokens are both counted. Model time covers only the provider request; end-to-end time starts before that request and ends after response parsing, SDK materialization where applicable, DXF writing, and independent validation. It excludes process setup, report writing, and any real AI-client/Skill overhead.

The negative B result matters: although the model returned fewer tokens, launching a new Node process for every KJDraw result made the whole route **slower** than direct DXF. Reusing one host removed that startup overhead in C; each request still creates a fresh KJDraw document. Within C, KJDraw used **40.9% fewer tokens** and **31.0% less summed end-to-end time** than direct DXF. These are three tasks on one Windows host and one model, not a universal performance estimate. The compact JSON adapter is a benchmark host, **not** the published `kjdraw-cad` Skill or production `agent call` interface. The full published tool schema has shown higher token use on tiny one-shot tasks in the [earlier study](deepseek-2026-09-28.md), and the generic annotated two-view manufacturing task has failed both arms. Do not cite this page as evidence that the shipped Skill is 40.9% cheaper or 31.0% faster.

The provider's Run C split shows the mechanism: KJDraw's compact route used **3,350 input / 1,290 output** tokens, while direct DXF used **2,840 input / 5,010 output**. KJDraw spent more input tokens on instructions but far fewer output tokens on serialized geometry; the totals above include both sides.

A separate clean-install `@kanjieteam/kjdraw@1.0.0-rc.3` check ran ten fresh `kjdraw agent call cad_propose_circles` processes on this Windows host: median **404.2 ms** per local proposal (range 357.3–452.9 ms). The [reproduction script](../../scripts/benchmarks/measure-agent-cli-startup.mjs) takes `--bin <path-to-installed-kjdraw.mjs> --runs 10`. This measures neither a model request nor review/export; it shows why C's persistent host cannot stand in for a terminal Skill that starts a CLI process per call.

Run C's task-level validity was mounting plate **5/5 versus 4/5**, bolt flange **5/5 versus 5/5**, and stepped profile **5/5 versus 0/5** (KJDraw versus direct DXF). All five direct stepped-profile outputs ended normally but failed the independent DXF structure parser. The aggregate therefore includes one task where both routes always worked and one where the direct route never did; it should not be read as an even advantage across drawing types.

## Manufacturing-sheet follow-up: two exploratory tasks

The separate `manufacturing-30` suite contains 30 dense, versioned fixtures. Before a large live run, its first attempt exposed a **benchmark defect**: the prompt omitted the intended annotation height while the validator required one exact height and the corresponding view placement. We stopped that attempt after 10 dispatches, kept it out of performance claims, added the explicit height to every prompt, and bumped the suite version to `1.0.1`. This was a scorer/prompt mismatch, not evidence that the SDK produced invalid geometry.

Separately, all **30 canonical structured inputs** materialized as editable KJD/DXF and passed the independent `ezdxf` contract in the offline test suite. That verifies the deterministic compiler and scorer against the fixture data; it does **not** measure how often a model extracts those inputs correctly from natural language.

We then made four fresh requests for the first two tasks under `v1.0.1`, again with `deepseek-flash`, temperature 0, thinking disabled, no retries, and the same 32,768 output-token cap per arm. The KJDraw manufacturing compiler passed independent `ezdxf` checks **2/2**, using 5,464 total provider-reported tokens and 6.232 summed end-to-end seconds. Direct ASCII DXF passed **0/2**; both responses ended at the output cap (`finish_reason=length`), using 66,224 total tokens and 151.200 summed end-to-end seconds. The [raw four-request archive](evidence/2026-09-29-deepseek-flash/README.md) includes both failures. This is a bounded **two-task exploratory** result, not a 30-task success rate, and it does not prove an uncapped or library-assisted direct route would fail. The strict manufacturing scorer checks a specified drawing profile, including native dimensions and layer conventions; its exact layout requirements make this unsuitable as a general CAD quality ranking.

A second, disjoint exploratory selection added one A2, one A1 and two A0 tasks, eight fresh requests total. KJDraw passed **4/4**, with 10,926 tokens and 13.970 summed end-to-end seconds. Direct DXF passed **0/4**, with 89,087 tokens and 207.492 seconds. Two direct responses reached the output cap; two stopped earlier but failed `ezdxf` structure validation. All four KJDraw DXFs and the two malformed direct DXFs were rechecked from saved artifacts by the offline auditor. Across the **six selected tasks**, KJDraw passed 6/6 and direct DXF 0/6, but selection was exploratory and is **not** a claim of 100% success over the 30-task suite or real engineering drawings.

We attempted the entire 30-task suite once more with an explicit 60-request budget. The provider returned **HTTP 402** on request 6, so the runner stopped without retrying: three KJDraw requests passed, two completed direct-DXF requests failed, and the third direct request has no model result. **54 requests were not run.** This interrupted run has its own raw archive and `--allow-stopped` offline audit; it must never be presented as a completed 30-task score. Additional live calls require the API account to be able to serve them.

## Reproduce or audit

The [raw evidence archives](evidence/2026-09-29-deepseek-flash/README.md) include every request, sanitized response, generated DXF where available, and `report.json`; the three one-shot archives also include offline `replay-report.json`. Failed cases are retained. Their SHA-256 hashes allow byte-for-byte verification. Run `scripts/benchmarks/replay-oneshot-study.py <extracted-archive> --assert-original` against an extracted one-shot archive, or `scripts/benchmarks/audit-manufacturing-evidence.py` against an extracted complete manufacturing archive, to check captured artifacts without making model calls. Add `--allow-stopped` only for the explicit HTTP 402 archive. The latter checks request/response/DXF hashes and revalidates every saved DXF; it does not rerun the model. A fresh live comparison requires your own DeepSeek key and may vary with provider behavior:

```powershell
python -m pip install -r scripts/benchmarks/requirements.txt
$secret = Read-Host -AsSecureString 'DeepSeek API key'
$plain = [System.Net.NetworkCredential]::new('', $secret).Password
$plain | python scripts/benchmarks/deepseek-oneshot-study.py --live --api-key-stdin --drawing-tool json
$plain = $null
$secret = $null
```

Do not put an API key in a command line, committed file, or issue. The script records source hashes and both timing definitions. This study is exploratory model evidence; an independently operated cross-model, cross-platform evaluation is still outstanding.
