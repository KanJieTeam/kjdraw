# KJDraw 1.0 产品边界

KJDraw 1.0 的定位是可嵌入的二维工程 CAD 基础设施，不是假装一次复制所有桌面 CAD 功能。稳定版承诺必须既能支撑真实应用，也能被公开、重复地验收。

## 1.0 稳定承诺

- 严格 TypeScript、ESM 优先的 SDK；自动生成类型声明，npm 运行时零依赖，根入口与子路径导出均有文档和编译验收。
- 事务化 KJD 图档：确定性命令、版本、撤销/重做、选择、捕捉和已声明的二维编辑能力。
- KJP 工程包：多图档、清单、快照、日志和完整性校验，并设置可配置的资源上限。
- 只对公开兼容矩阵中的 ASCII DXF 实体、资源和版本做互操作承诺；遇到未支持语义必须明确报告，不暗示任意 DXF 无损。
- 中英文浏览器工作台通过同一套公开 SDK 完成打开、查看、绘制、编辑、审阅、撤销、保存和重开。
- Agent 修改计划采用版本化密码学内容绑定、过期控制、一次性执行和可审计回执；身份与授权仍由宿主负责。
- 可选 Rust/WebAssembly 权威层与部署 Provider 合约，降级路径和网络行为必须明确。
- React、Vue 示例必须针对同一个 npm 打包产物实际编译。
- 版本化文档、自动 API Reference、可复现实验、性能预算，以及带 provenance/签名证明的发布产物。

## 明确不属于 1.0 的范围

1.0 不承诺 DWG、任意 DXF 无损转换、通用 BRep、完整参数化约束、实时协作、专有行业模板、完整字体/布局保真和设备认证打印。实验性网格能力必须继续标注为实验性。插件权限声明属于协作式合约，恶意代码隔离由宿主进程或沙箱负责。

这些不是被隐藏的缺陷。任何一项未来若要进入正式承诺，都必须单独定义公开合约、合法来源、兼容语料和可执行验收证据。

## 晋级规则

只有 [`KJDRAW_1_0_ACCEPTANCE_MATRIX.json`](KJDRAW_1_0_ACCEPTANCE_MATRIX.json) 中所有 `requiredForStable` 项在同一个候选提交上通过，才创建稳定标签；npm 包、在线 Demo、版本化 Docs 与 GitHub Release 必须对应同一提交。社区热度不能靠口号保证，但可信边界和可复验证据必须保证。
